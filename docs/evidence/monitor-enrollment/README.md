The held-probe cases preserve two different local lifecycle outcomes. Forced native eviction waited for the monitor timeout: its revision-1 timeout check was already stored when eviction returned, while the synthetic origin was still held. Configuration reload instead rejected the old proxy; native storage contained zero old-slot checks both when reload returned and after releasing the origin and waiting another 3,100 ms. A new revision-2 observation restored readiness. Proxy rejection alone is not native completion acknowledgement; the test separately samples persisted state. These results do not establish Cloudflare deployment propagation or global replacement behavior.

[Cloudflare's global uniqueness contract](https://developers.cloudflare.com/durable-objects/platform/known-issues/#global-uniqueness) separately states that replacement is enforced at event start and storage access; an old invocation's later storage access receives an exception. Monitor completion accesses storage before inserting a check. [Code updates](https://developers.cloudflare.com/durable-objects/platform/known-issues/#code-updates) can still briefly mix Worker and Durable Object versions before cutover. That source-based reasoning is separate from the local reload experiment; no production race was reproduced or repaired.
